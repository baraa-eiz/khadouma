# 08. Service Layer Design (طبقة الخدمات ومنطق الأعمال)

توثق هذه الصفحة تصميم ومسؤوليات طبقة الخدمات (Services) كحلقة الوصل المحورية بين المتحكمات والمستودعات.

---

## 1. دور طبقة الخدمات (Responsibilities)

تعتبر طبقة الخدمات هي مستودع منطق الأعمال (Business Logic) الوحيد في التطبيق. تشمل مهامها:
* **تنسيق المعاملات (Transaction Orchestration):** تنفيذ عمليات قاعدة البيانات التي تتطلب التعديل في عدة جداول بشكل متتالي وبدء التراجع (Rollback) في حال فشل أي منها.
* **تطبيق قواعد الأعمال:** التحقق من إمكانية تغيير حالة الحرفي، والتأكد من أمان كتابة المراجعات وتحديد من له حق التعديل.
* **الربط مع الخدمات الخارجية والمساعدة:** إرسال رسائل التحقق (SMS)، معالجة ورفع الملفات عبر محرك الوسائط، وتدوين سجلات التدقيق الإداري.

---

## 2. قائمة الخدمات البرمجية المعتمدة (Core Services)

1. **خدمة الحرفيين (`ProviderService`):**
   * تسجيل حرفي جديد، تحديث البيانات التجارية، إضافة مناطق عمل أو مهارات إضافية، وتعديل حالة الاعتماد.
2. **خدمة المراجعات والتقييمات (`ReviewService`):**
   * إرسال التقييمات، تصفية المحتوى المسيء تلقائياً، إعتماد المراجعة من الإدارة، وإعادة حساب التقييم العام للحرفي.
3. **خدمة رفع الميديا (`MediaService`):**
   * التحقق من سلامة الملفات المرفوعة، معالجة الصور وتحويلها إلى WebP، استخراج الصور المصغرة، ونسخ الملفات الخاصة لمجلدات الحماية.
4. **خدمة الإدارة والمصادقة (`AuthService`):**
   * التحقق من كلمات مرور المشرفين، إدارة الجلسات المؤمّنة، وإتلاف الكوكيز عند تسجيل الخروج.
5. **خدمة الإحصاء والتدقيق (`AuditService`):**
   * تسجيل حركات المشرفين وتسجيل أحداث النقر للزوار لتقييم فائدة الحرفيين.

---

## 3. محظورات طبقة الخدمات (What NOT to place here)

* **لا تتعامل الخدمات مع بروتوكول HTTP مباشرة:** يجب ألا تستخدم مصفوفات الطلب العامة مثل `$_POST` أو `$_GET`؛ بل يجب أن تتلقى مدخلاتها كمتغيرات ممررة أو كائنات بيانات مبسطة (DTOs).
* **لا تولد الخدمات واجهات HTML:** يقتصر عملها على إرجاع كائنات استجابة، مصفوفات بيانات، أو رمي استثناءات (Exceptions) عند الفشل.
* **لا تحتوي على استعلامات SQL خام:** لا تتصل بقاعدة البيانات مباشرة، بل تستدعي دوال المستودعات (`Repositories`).

---

## 4. آلية معالجة المعاملات (Database Transactions)

عند الحاجة لتعديل أكثر من جدول بشكل متزامن (على سبيل المثال: تسجيل حرفي جديد وتخزين مناطق عمله وخدماته)، يجب استخدام المعاملات لضمان عدم تلف البيانات المرجعية في حال حدوث عطل جزئي:

```php
// نمط المعالجة الموصى به داخل طبقة الخدمات
public function registerProvider(ProviderData $data): bool 
{
    $db = Database::getInstance();
    $db->beginTransaction();
    
    try {
        // 1. حفظ الحرفي الأساسي والحصول على المعرّف
        $providerId = $this->providerRepo->create($data);
        
        // 2. ربط الخدمات المختارة
        $this->providerRepo->assignServices($providerId, $data->services);
        
        // 3. ربط مناطق التغطية
        $this->providerRepo->assignAreas($providerId, $data->areas);
        
        // 4. كتابة سجل تدقيق للعملية
        $this->auditRepo->log("provider_registered", $providerId);
        
        $db->commit();
        return true;
    } catch (Exception $e) {
        $db->rollBack();
        throw $e; // إعادة رمي الاستثناء للمتحكم لعرض رسالة خطأ مناسبة
    }
}
```
