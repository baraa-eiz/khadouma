# 01. Architecture Overview (نظرة عامة على البنية البرمجية)

تم تأسيس منصة **خدومة** لتكون دليلاً ووسيطاً محلياً سورياً للحرف والخدمات المنزلية. هذا المستند يوثق فلسفة التصميم المعماري للمنصة والقرارات الهندسية الكبرى.

---

## 1. فلسفة المعمارية المصغرة (Why Micro-MVC?)

تم اعتماد نمط **Micro-MVC** (المتحكم والنموذج والعرض المصغر) لتحقيق الأهداف التالية:
* **عزل المسؤوليات (Separation of Concerns):** يتم إبعاد المنطق العملياتي وقاعدة البيانات تماماً عن العروض والـ HTML.
* **الحجم الأدنى والأداء الأقصى:** بدلاً من استخدام أطر عمل كاملة تستهلك المئات من الكوكيز والمصفوفات والذاكرة، تم تطوير معمارية خفيفة للغاية تناسب الخوادم الضعيفة وسرعات الإنترنت البطيئة في سوريا.
* **مرونة الصيانة:** يسهل تتبع وتعديل المسارات والأكواد دون الخوف من كسر عناصر الواجهات الرسومية.

---

## 2. مبررات استخدام لغة PHP النظيفة (Why Native PHP?)

تظل PHP النظيفة (Native PHP 8.x) الخيار الأمثل لهذا المشروع للأسباب التالية:
* **زمن معالجة سريع جداً:** انخفاض وقت الاستجابة (Latency) إلى ما دون 50 مللي ثانية نظراً لعدم وجود معالجة مسبقة ثقيلة لملفات التكوين.
* **الحد الأدنى من استهلاك الذاكرة:** تشغيل خفيف بأقل من 2 ميغابايت من الذاكرة العشوائية لكل طلب.
* **سهولة التثبيت والتشغيل:** التوافق التام مع أي خادم XAMPP محلي أو خادم VPS مشترك دون تعقيدات سطر الأوامر أو الاعتماد على مدير حزم خارجي.

---

## 3. حماية مجلد الجذر العام (Why Public Folder Isolation?)

تم تصميم النظام بحيث يكون مجلد `/public` هو المجلد الوحيد المتاح للوصول العام عبر الويب (Web-Accessible Document Root).

**الأهمية الأمنية:**
* **منع الوصول للملفات الحساسة:** حماية ملفات الإعدادات وثوابت قاعدة البيانات في `/config` ومنع استعراضها.
* **منع تشغيل الأكواد العشوائية:** عزل ملفات الـ Views والـ Repositories في بيئة داخلية بحيث لا يستطيع الزائر استدعاءها مباشرة عبر المتصفح.
* **نقطة دخول موحدة:** يمر كل طلب حصرياً بـ `/public/index.php` مما يسمح بتفعيل الفلاتر الأمنية ومحرك المسارات بشكل مركزي ومضمون.

---

## 4. عزل الطبقات (Controller / Service / Repository / View)

يقسم تدفق البيانات البرمجية إلى أربع طبقات واضحة:
1. **المتحكم (Controller):** يستقبل طلبات HTTP، ويستدعي المدققين (Validators)، ويوجه المدخلات إلى طبقة الخدمات (Services)، ثم يعيد الاستجابة أو يمرر البيانات للمنسق.
2. **الخدمة (Service):** تحتوي على منطق العمل الحقيقي (Business Logic) والتحقق الإداري والمعاملات المالية وحساب الحالات.
3. **المستودع (Repository):** مسؤول حصرياً عن جلب وتخزين البيانات من وإلى قاعدة البيانات (SQL queries) دون اتخاذ قرارات منطقية.
4. **العرض (View):** واجهة HTML نقية تستخدم معالجات النصوص المساعدة لعرض البيانات للزائر بأمان (عبر `e()`).

---

## 5. محاربة الهندسة المفرطة (Avoiding Over-Engineering)

تلتزم المنصة بمبدأي **KISS** (حافظ عليها بسيطة) و **YAGNI** (لن تحتاجها الآن):
* **لا نستخدم Redis** في النسخة الأولى؛ نكتفي بذاكرة MySQL والـ OPcache الافتراضي.
* **لا نستخدم أنظمة صفوف رسائل معقدة (Message Queues)**؛ يتم معالجة العمليات والرفع مباشرة في الطلب أو عبر مهام مجدولة بسيطة (Cron).
* **لا نستخدم محركات قوالب معقدة (Twig/Blade)**؛ نعتمد على قوالب PHP النظيفة التي تدعمها محركات الخادم مباشرة دون تكاليف معالجة إضافية.
