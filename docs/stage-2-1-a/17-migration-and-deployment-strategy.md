# 17. Migration and Deployment Strategy (خطة التهجير والتهيئة البرمجية)

يوضح هذا المستند بيئة العمل المعتمدة ومراحل نقل وتهيئة قاعدة البيانات والمشروع بين بيئة التطوير المحلية (XAMPP) وخادم الإنتاج VPS.

---

## 1. مواصفات بيئة التطوير المحلية (Local Development)

* **البيئة المعتمدة:** XAMPP (Apache + PHP 8.x + MariaDB).
* **مسار المجلد المحلي:** `C:\xampp\htdocs\khadomeh\`
* **رابط الموقع المحلي:** `http://localhost/khadomeh/public/` (أو إعداد Virtual Host ليشير إلى `http://khadomeh.local`).
* **قاعدة البيانات المحلية:** `khadomeh_db`
* **الترميز الافتراضي:** `utf8mb4` وترتيب الفرز `utf8mb4_unicode_ci` لدعم كامل وفهرسة دقيقة للحروف والرموز العربية.

---

## 2. إدارة ملفات تحديث قاعدة البيانات (Database Migrations)

لتفادي التعديل اليدوي العشوائي لقاعدة البيانات في السيرفر وتجنب فقدان البيانات، نستخدم نظام تهجير برميجي مبسط (Simple Migration Runner):
* **تخزين التحديثات:** تُحفظ التحديثات في مجلد `/database/migrations/` وتسمى بناءً على الترتيب الزمني للتنفيذ:
  * `0001_create_initial_schema.sql`
  * `0002_add_verification_states.sql`
  * `0003_add_public_id_to_providers.sql`
* **جدول تتبع الإصدار (`schema_versions`):** جدول داخل قاعدة البيانات يسجل اسم كل ملف تم تنفيذه وتاريخ تنفيذه.
* **آلية التنفيذ:** عند رفع ملفات تحديث جديدة، يقرأ السيرفر جدول `schema_versions` ويقوم بتشغيل الملفات الجديدة غير المسجلة تلقائياً عبر واجهة التطوير أو عبر تشغيل كود محمي من المتصفح (مثال: `/admin/migrations/run`) لتفادي كتابة استعلامات يدوية مكررة.

---

## 3. تكوين البيئة المشتركة وملف الإعدادات (`.env` Strategy)

لمنع كشف كلمات مرور الإنتاج محلياً وتسهيل التبديل التلقائي للإعدادات:
* يتم إنشاء ملف **`.env`** في مجلد المشروع الرئيسي (خارج المجلد العام) يحتوي على المتغيرات الأساسية:
  ```ini
  DB_HOST=127.0.0.1
  DB_NAME=khadomeh
  DB_USER=khadomeh_user
  DB_PASS=kH3d0M3h_db_p@ss_2026!
  ENVIRONMENT=production ; local / production
  ```
* يتم تجاهل ملف `.env` الفعلي في مستودع الكود عبر `.gitignore`.
* يتم رفع نموذج الإعدادات الافتراضي `config.example.php` أو `.env.example` للمطورين الجدد.
* يقرأ النظام في `config/database.php` القيم من ملف الـ `.env` عند بدء التشغيل، ويفشل برمجياً برسالة واضحة في حال عدم وجود الملف.

---

## 4. استراتيجية النشر والرفع (VPS Deployment Steps)

تتم عملية النشر بطريقة خطية آمنة:
1. دفع الأكواد والتغييرات إلى الفرع الرئيسي لمستودع الكود (Git).
2. تشغيل الرفع التلقائي (أو استخدام الـ SCP الآمن عبر مفتاح SSH المعتمد).
3. تشغيل كود المزامنة والتحقق من الصلاحيات وتغيير مالك المجلدات والملفات المرفوعة إلى مستخدم الخادم (`cnc-jordan-service`).
4. الدخول إلى لوحة التحكم الإدارية لتشغيل الـ Migrations الجديدة (إن وجدت) والتحقق من اتصال قاعدة البيانات وسجلات الأخطاء.
