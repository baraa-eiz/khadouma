# 13. Search Architecture (معمارية وفلسفة محرك البحث المدمج)

يوضح هذا المستند تصميم محرك البحث العام في منصة خدومة، وكيفية معالجة الحروف والكلمات العربية لضمان الوصول لأدق النتائج بأقل استهلاك لموارد السيرفر.

---

## 1. تجريد واجهة البحث (Search Abstraction)

لتفادي الارتباط المباشر بطريقة استعلام واحدة، تم تصميم محرك البحث باستخدام واجهة موحدة (`SearchEngineInterface`) تسهل استبدال طريقة البحث مستقبلاً دون تغيير أي كود في المتحكمات.

```php
namespace App\Services\Search;

interface SearchEngineInterface 
{
    /**
     * تنفيذ البحث عن الحرفيين بناءً على مصفوفة فلاتر معينة.
     * 
     * @param string $query النص المكتوب للبحث
     * @param int|null $cityId معرّف المحافظة
     * @param int|null $serviceId معرّف الخدمة
     * @param array $options خيارات إضافية مثل الترتيب والصفحات
     * @return array قائمة الحرفيين المطابقين
     */
    public function search(string $query, ?int $cityId = null, ?int $serviceId = null, array $options = []): array;
}
```

---

## 2. تنفيذ النسخة الأولى (V1.0 Simple SQL Search)

في المرحلة الأولى، سيتم اعتماد فئة `SimpleSearchEngine` التي تطبق الواجهة وتعتمد على استعلامات SQL القياسية لضمان العمل على أي بيئة مشتركة أو خادم ضعيف دون متطلبات خاصة:
* **البحث المعتمد على الفهارس:** يتم فلترة النتائج أولاً باستخدام المفاتيح الخارجية المفرسة (`city_id`, `service_id`) لتقليص حجم البيانات المستهدفة.
* **البحث المطابق المباشر:** استخدام جمل `LIKE %term%` على الحقول النصية المعقمة مثل اسم الحرفي وسيرته الذاتية.

---

## 3. تطبيع الكلمات العربية (Arabic Normalization Process)

نظراً لاختلاف طرق كتابة الحروف العربية (مثل الهمزات، والتاء المربوطة، والألف المقصورة) وكثرة الأخطاء الإملائية الشائعة لدى المستخدمين، يتبع النظام الآلية التالية في مطابقة نصوص البحث:

1. **دالة المساعد المركزي `normalize_arabic($text)`:**
   * تحويل جميع أشكال الألف (أ، إ، آ) إلى ألف مجردة (ا).
   * تحويل التاء المربوطة (ة) في نهاية الكلمات إلى هاء (ه).
   * تحويل الياء المقصورة (ى) إلى ياء بنقطتين (ي).
   * سحب وإزالة كافة علامات التشكيل (الفتحة، الضمة، الكسرة، التنوين) والمد الطويل.
2. **التنفيذ أثناء الاستعلام:**
   * يتم تطبيق هذه الدالة على كلمة البحث المدخلة من الزائر.
   * يتم مطابقتها مع الحقول المخزنة والمطهرة مسبقاً في قاعدة البيانات لضمان الوصول للنتيجة حتى لو اختلفت طريقة كتابة الهمزة في اسم الحرفي عن النص الذي كتبه الباحث.

---

## 4. خطة الترقية المستقبلية (Future Upgrade Paths)

عند نمو المنصة وزيادة أعداد الحرفيين لآلاف السجلات، يمكن بسهولة كتابة فئة جديدة:
* **`FullTextSearchEngine` (الخطوة التالية):** تفعل فهارس الـ FULLTEXT الخاصة بمحرك MySQL/MariaDB مما يتيح الترتيب بناءً على درجة المطابقة (Relevance Scoring) والبحث عن الكلمات الجزئية بسرعة متناهية ودون استهلاك ذاكرة إضافية.
* **الدمج:** لتفعيل المحرك الجديد، نقوم بتعديل سطر الربط في حاوي الخدمة (Service Container/Config) ليشير إلى الفئة الجديدة دون لمس كود شاشات البحث العامة على الإطلاق.
