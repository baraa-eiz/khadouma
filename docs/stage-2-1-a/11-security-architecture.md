# 11. Security Architecture (بنية الحماية والأمان)

يوضح هذا المستند التدابير الأمنية المطبقة لحماية منصة خدومة من الثغرات البرمجية وحماية بيانات المستخدمين والحرفيين.

---

## 1. محاور الحماية البرمجية (Core Security Safeguards)

### أ. تشفير كلمات المرور (Password Hashing)
* يتم تشفير جميع كلمات مرور المشرفين باستخدام خوارزمية **`PASSWORD_BCRYPT`** القوية عبر دالة `password_hash()` الافتراضية في PHP.
* يمنع النظام تماماً تخزين كلمات المرور بصيغتها المقروءة أو فك تشفيرها؛ بل يتم مطابقتها حصراً عبر `password_verify()`.

### ب. حماية الجلسات (Secure Session Management)
* يتم تفعيل بارامترات الأمان للجلسات في ملف `includes/init.php` قبل بدء أي جلسة:
  ```php
  ini_set('session.cookie_httponly', 1); // منع الوصول للجلسة عبر جافا سكربت (anti-XSS)
  ini_set('session.cookie_secure', 1);   // فرض إرسال الكوكي عبر الاتصال المشفر HTTPS فقط
  ini_set('session.use_only_cookies', 1); // منع تمرير معرّف الجلسة في الروابط العامة
  ini_set('session.cookie_samesite', 'Lax'); // حماية الجلسة من هجمات تزوير الطلبات العابرة للمواقع
  ```

### ج. منع تزوير الطلبات عابرة المواقع (Anti-CSRF)
* توليد كود عشوائي فريد لكل جلسة `$_SESSION['csrf_token']` عند تحميل النماذج (Forms).
* تضمين حقل مخفي `csrf_field()` في جميع نماذج الإرسال (POST).
* يقوم نظام الأمان المركزي بالتحقق من مطابقة الرمز في السيرفر قبل معالجة أي طلب تعديل أو كتابة، ويرفض الطلب فوراً باستجابة `403 Forbidden` في حال عدم المطابقة.

### د. منع البرمجة العابرة للمواقع (Anti-XSS Escaping)
* تعقيم وتطهير كافة المخرجات المعروضة للمستخدم والآتية من قاعدة البيانات باستخدام دالة المساعد `e()` التي تلتف حول `htmlspecialchars($str, ENT_QUOTES, 'UTF-8')`.
* منع محركات المتصفح من تشغيل الأكواد المحقونة في النصوص والتعليقات.

### هـ. منع حقن استعلامات قاعدة البيانات (Anti-SQL Injection)
* فرض استخدام الاستعلامات المجهزة المسبقة (**Prepared Statements**) التي يدعمها كائن PDO داخل جميع فئات المستودعات (`Repositories`).
* يمنع تماماً دمج المتغيرات النصية بشكل مباشر داخل نصوص الاستعلامات SQL.

---

## 2. حماية الوثائق والملفات الخاصة (Private Upload Protection)

لمنع المتطفلين من تصفح أو تحميل وثائق الهوية والشهادات الحساسة الخاصة بالحرفيين:
1. **عزل الملفات:** يتم حفظ وثائق التحقق والشهادات في مجلد `/storage/secure_uploads/` الواقع خلف مجلد الويب العام.
2. **منع الاستعراض المباشر:** لا توجد روابط مباشرة (URLs) تشير إلى هذه الملفات على الإطلاق.
3. **التحميل المحمي (Authenticated Download Guard):** عند رغبة المدير بمراجعة وثيقة، يطلبها عبر رابط خاص (مثال: `/admin/documents/view?id=123`). يقوم المتحكم بالتحقق من جلسة المدير وصلاحياته أولاً، ثم يقوم بقراءة الملف من المجلد المحمي وإرساله للمتصفح عبر رؤوس استجابة خفيفة (Binary Stream Headers) دون كشف مكانه الفعلي على الخادم.

---

## 3. محدد معدل الطلبات وحماية الاستمارات (Rate Limiting Design)

لحماية النماذج العامة (مثل إرسال تقييم أو كتابة بلاغ) من هجمات الإغراق والـ DOS:
* يخزن النظام بصمة الـ IP ووقت الإرسال الأخير لكل مستخدم في جلسة المتصفح أو جدول مؤقت خفيف.
* يمنع المستخدم من إرسال أكثر من تقييم واحد كل 5 دقائق لنفس الحرفي، وأكثر من 3 بلاغات في الساعة الواحدة.
